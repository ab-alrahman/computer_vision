# تقرير مشروع نظام المرور الذكي

## 1. فكرة المشروع

المشروع عبارة عن نظام رؤية حاسوبية لتحليل فيديو مأخوذ من طريق مدفوع. يقرأ النظام الفيديو إطاراً بعد إطار، ويكتشف المركبات الموجودة في الطريق، ثم يصنفها ويتتبع حركتها ويحسب عدد المركبات التي عبرت خط العد.

الهدف النهائي هو معرفة عدد المركبات حسب نوعها واتجاهها، وحساب الرسوم المترتبة عليها، مع تسجيل مخالفات السرعة وتنبيه النظام عند مرور دراجة نارية عادية. أما دراجة شرطة المرور فهي الفئة المسموح بها من الدراجات.

الفئات المستخدمة في النظام هي:

- `car`: سيارة.
- `van`: فان.
- `bus`: باص.
- `truck`: شاحنة.
- `motorcycle`: دراجة نارية عادية.
- `traffic-police motorcycle`: دراجة شرطة المرور.

## 2. طريقة عمل النظام

يمر الفيديو بالمراحل التالية:

1. قراءة الفيديو بواسطة OpenCV.
2. تحسين الصورة عند الحاجة باستخدام إزالة الضجيج وCLAHE والـ sharpening.
3. اكتشاف المركبات باستخدام نموذج YOLO11n المدرب.
4. إعطاء كل مركبة صندوقاً محيطاً ودرجة ثقة وفئة.
5. تتبع المركبات بين الإطارات باستخدام Centroid Tracker حتى لا تُحسب المركبة أكثر من مرة.
6. تحديد عبور المركبة لخط العد ومعرفة اتجاهها.
7. تطبيق قواعد المشروع، مثل حساب الرسم أو تسجيل مخالفة دراجة نارية أو مخالفة سرعة.
8. رسم النتائج على الفيديو.
9. إنشاء تقرير JSON نهائي يحتوي على أعداد المركبات والإيرادات والمخالفات.

## 3. الأدوات المستخدمة

تم استخدام Python وOpenCV لمعالجة الفيديو، ومكتبة Ultralytics لتشغيل YOLO11n، وNumPy وPyYAML وPillow لمعالجة البيانات والإعدادات. يعتمد التتبع على كود المشروع الموجود في `src/pipeline/tracker.py`، بينما توجد قواعد الرسوم والمخالفات في `src/pipeline/rules.py`.

النموذج الأساسي هو `models/yolo11n.pt`، أما النموذج المستخدم في التشغيل فهو `models/best.pt`.

## 4. إعداد البيانات والتدريب

### 4.1 تفاصيل جمع بيانات الفان وتجارب التدريب

كانت مسؤولية هذا الجزء هي تدريب النموذج، لذلك بدأت العملية بالبحث عن بيانات مناسبة للمركبات. تم البحث في مصادر معروفة مثل **Open Images** و**Kaggle**، إضافة إلى عدة مصادر أخرى.

في البداية تم تنزيل عدة مكتبات جاهزة مرتبطة بـ Open Images، وكانت الفكرة أن يتم تجهيز البيانات وتنزيلها مباشرة داخل مجلد المشروع من دون تنزيل مجلد منفصل. لكن المحاولات لم تنجح بالشكل المطلوب؛ ففي بعض الأحيان كان البرنامج يتوقف أو يعلّق، وفي محاولات أخرى لم يبدأ التنزيل أساساً. لذلك تم الانتقال إلى حل عملي، وهو تنزيل البيانات على شكل مجلد مضغوط `ZIP` ثم فك ضغطه وتجهيزه داخل المشروع.

بعد مقارنة المصادر، كان مصدر **Roboflow** أفضل مصدر تم الوصول إليه لتنزيل البيانات. بدأت التجربة الأولى بتنزيل صور الفان، وكان عددها تقريباً **2000 صورة**. تم تدريب النموذج على هذه البيانات، واستغرق التدريب قرابة **ساعتين**، لكن النتيجة كانت ضعيفة نسبياً.

بسبب ضعف النتيجة، تم توسيع مجموعة البيانات، فأصبح عدد الصور أكثر من **11000 صورة**. بعد إعادة تدريب النموذج على العدد الأكبر، أصبحت النتيجة **ممتازة بشكل واضح مقارنة بالتجربة الأولى**، إلا أن التدريب استغرق وقتاً أطول، وصل إلى قرابة **ثماني ساعات**.

### 4.2 تفاصيل جمع بيانات دراجة شرطة المرور وتجارب التدريب

بعد الانتهاء من تجربة الفان، تم الانتقال إلى فئة دراجة شرطة المرور. تم البحث عن بيانات جاهزة لهذه الفئة في المصادر المتاحة، لكن لم يتم العثور على مجموعة مناسبة يمكن استخدامها مباشرة. لذلك جُمعت الصور يدوياً من Google.

في التجربة الأولى تم جمع حوالي **30 صورة** فقط، ثم تطبيق عملية **Augmentation** عليها. نتج عن ذلك توزيع تقريبي للبيانات قدره **300 صورة للتدريب، و100 صورة للتحقق، و60 صورة للاختبار**. بعد تدريب النموذج على هذه البيانات، كانت النتيجة غير صحيحة.

بعد مراجعة المشكلة والاستعانة بأدوات الذكاء الاصطناعي، ظهر أن أحد أسباب المشكلة هو تدريب النموذج على بيانات مكررة أو متشابهة في جميع المراحل. لا يصح أن تكون صور التدريب نفسها، أو نسخ قريبة جداً منها، موجودة في مرحلتي التحقق والاختبار؛ لأن ذلك يسبب تداخلاً بين مجموعات البيانات ويجعل نتيجة التقييم غير موثوقة.

بناءً على ذلك، تم تجهيز مجموعة جديدة قوامها تقريباً **100 صورة**، ثم تطبيق زيادة البيانات عليها مع محاولة فصل مجموعات التدريب والتحقق والاختبار. أصبح التوزيع التقريبي **400 صورة للتدريب، و36 صورة للتحقق، و26 صورة للاختبار**. تم تدريب النموذج مرة أخرى، لكن النتيجة بقيت غير صحيحة.

في تجربة ثالثة تم تقليل تكرار كل صورة، بحيث لا يتم استخدام نسخ كثيرة من الصورة نفسها ضمن التدريب. أدى ذلك إلى أن يصبح عدد بيانات التدريب قرابة **200 صورة**. تم تدريب النموذج على هذا التوزيع أيضاً، لكن النتيجة بقيت غير صحيحة.

وبذلك كانت نتيجة التجارب أن زيادة عدد الصور حسّنت نموذج الفان بشكل كبير، بينما لم تكن زيادة البيانات وحدها كافية للوصول إلى نتيجة صحيحة في فئة دراجة شرطة المرور. ومن الأسباب المحتملة لذلك قلة الصور الأصلية، وضعف التنوع بين الصور، وصعوبة التمييز بين دراجة الشرطة والدراجة العادية، إضافة إلى حساسية الوسوم واختلاف الزوايا والإضاءة.

هذه التجربة لم تُعتبر نتيجة نهائية ناجحة، ولذلك يجب تحسينها مستقبلاً بجمع صور أصلية أكثر، ومراجعة الوسوم يدوياً، وإضافة صور سلبية لدراجات عادية.

## 5. إعدادات النظام

توجد إعدادات التشغيل في `configs/default.yaml`. أهم الإعدادات هي:

- النموذج: `models/best.pt`.
- حد الثقة العام: `0.35`.
- خط العد: محدد بنقطتين داخل الملف.
- حد السرعة: 80 كم/ساعة.
- أسعار العبور: السيارة 1، الفان 1.5، الباص 2، والشاحنة 2.5.
- رسوم الدراجات مضبوطة على صفر لأنها ليست مركبات مدفوعة في هذا السيناريو.

توجد إعدادات التدريب الكاملة في `configs/train.yaml`، وتجربة الفان في `configs/train_van.yaml`، وتجربة دراجة الشرطة في `configs/train_police_bike.yaml`.

## 6. النتائج والمخرجات

ينتج التشغيل فيديو جديداً تظهر عليه صناديق المركبات والفئة والبيانات المباشرة مثل عدد المسارات والمخالفات. كما ينتج تقريراً بصيغة JSON يتضمن عدد المركبات، اتجاه العبور، مجموع الإيرادات، ومعلومات المخالفات.

يتم حفظ النتائج افتراضياً في:

```text
runs/vision/output.mp4
runs/vision/report.json
```

## 7. طريقة التشغيل

من داخل مجلد المشروع:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

بعدها شغّل اختباراً قصيراً:

```powershell
python -m src.main --config configs/default.yaml --max-frames 15
```

إذا نجح الاختبار، شغّل الفيديو كاملاً:

```powershell
python -m src.main --config configs/default.yaml --all-frames
```

إذا كان اسم الفيديو مختلفاً، افتح `configs/default.yaml` وعدّل السطر:

```yaml
input: data/raw/video/Road traffic video for object recognition.mp4
```

## 8. إعادة التدريب عند الحاجة

للتأكد من إعدادات التدريب دون تنفيذ تدريب طويل:

```powershell
python scripts/train.py --config configs/train.yaml --smoke --no-export
```

للتدريب الكامل:

```powershell
python scripts/train.py --config configs/train.yaml --eval-test
```

يحتاج التدريب الكامل إلى وقت طويل، خصوصاً عند التشغيل على CPU. لذلك عند فحص المشروع يكفي استخدام النموذج الموجود في `models/best.pt` وتشغيل النظام مباشرة.

## 9. محتويات التسليم

يجب أن يتضمن المشروع مجلدات `src` و`configs` و`scripts` و`models`، وملف `requirements.txt`، وملفات YAML الموجودة في `data`. يجب أيضاً إرسال الفيديو إذا كان الفاحص سيشغّل النظام، أو تعديل مساره في `configs/default.yaml`.
